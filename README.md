- 게임에 있는 모델을 그대로 쓰기 때문에 **따로 배포하는 번들 파일이 없습니다** (녹턴 주사기와 같은 방식).
- 진짜 열쇠를 같이 갖고 있으면 **진짜 열쇠가 먼저 쓰입니다** — 알리바바 아이템의 횟수는 다른 방법이 없을 때만 줄어듭니다.
- 카드 리더 앞에서는 기존처럼 "키카드 사용 시도" 목록에 `알리 카드`가 같이 뜹니다.
- **어느 아이템이 여는지는 "그 잠금이 원래 요구하는 열쇠의 종류"로 정합니다**: 키카드면 키카드, 이름에 marked가 붙은 열쇠면 마크방 열쇠, 그 밖의 열쇠면 일반 열쇠.
  그래서 **WTT-Backport 같은 모드가 추가한 열쇠·키카드**(예: Admin's key, 쇄빙선 Boreas 키카드, Armory key 등)가 필요한 문도 따로 목록 없이 같은 규칙으로 열립니다.
  모드 열쇠 중 영어 이름에 "marked"가 들어간 것은 서버가 찾아서 마크방 열쇠 쪽으로 넣습니다(서버 로그 `marked-room key covers N key(s)`).
- **탈출구**: 열쇠·키카드를 "갖고 있어야" 하는 탈출구에서 알리바바 아이템을 대신 인정합니다. 진짜 열쇠도 탈출할 때 닳지 않으므로 알리바바 아이템도 닳지 않습니다.
- **연구소 입장**: 연구소 출입증을 **장착(주머니·특수 슬롯 등 장비 안)** 하고 들어가면 됩니다. 들어갈 때마다 **사용 횟수가 1회 줄고**, 다 쓰면 사라집니다(무제한이면 안 줄어듦).
  진짜 1회용 출입 카드도 같이 갖고 있으면 게임이 먼저 찾은 쪽을 씁니다.
- **래버린스 입장**: 래버린스 출입증으로 똑같이 됩니다(래브리스 출입 카드 대신). 연구소 출입증과 래버린스 출입증은 서로의 맵에는 못 씁니다.
- **툴팁**: 출입증은 "남은 입장 횟수 3/10회"(영어 설정이면 "Entries left 3/10"), 나머지는 게임 기본 "남은 사용 횟수"로 나옵니다. 무제한이면 "무제한" 표시.
  F12에서 횟수·무제한을 바꾸면 이미 가진 아이템의 표시도 바로 바뀝니다.
- 출입증도 키카드라서 카드 리더 앞 "키카드 사용 시도" 목록에 뜨지만, 대 보면 열리지 않습니다(다른 맞지 않는 카드와 같음).
- 플리마켓은 SPT 기본 설정상 **레벨 15부터** 열립니다.

### 어디서도 공짜로 안 나오게 한 것

기본값(등장 확률 0%)이면 아래 어디에서도 안 나옵니다.

- 맵 바닥 루트, 모든 컨테이너(마크방 포함), 봇(스캐브·PMC·보스) 소지품 — 확률이 0이면 루트 테이블에 아예 넣지 않습니다
- 펜스, 에어드랍, 스캐브 케이스, PMC 랜덤 루트 (SPT의 보상 블랙리스트에 등록 — 확률과 관계없이 항상)
- 퀘스트 보상·하이드아웃 제작에는 원래 없음

## F12 설정

게임 안에서 **F12** → `Ali Baba's Treasure`. 맨 위 **`00. Language · 언어`** 에서 한국어/English를 고릅니다
(자동 = 한국어 윈도우면 한국어, 아니면 영어). 언어를 바꾼 뒤에는 **F12 창을 닫았다 다시 열면** 바뀝니다.
이 항목 이름은 언어와 관계없이 두 언어로 같이 써 있어서, 한국어로 되어 있어도 영어 사용자가 찾을 수 있습니다.
같은 칸의 **`모든 등장 확률 0으로 · Reset spawn chances`** 를 체크하면 모든 아이템의 등장 확률이 0으로 돌아갑니다(체크는 저절로 풀림).

### 디버그 모드 (테스트·문제 제보용)

같은 칸의 **`디버그 모드 · Debug mode`** 를 켜면 로그에 판정 과정이 남습니다. 평소에는 꺼 두세요(켜 둬도 렉은 거의 없지만 로그가 길어집니다).

| 어디에 | 무엇이 남나 (줄 앞머리) |
|---|---|
| `BepInEx/LogOutput.log` | `[Alibaba] Lock '…' wants …` — 잠금이 요구하는 열쇠, 대신 필요한 알리바바 아이템, 갖고 있는지 |
| | `[Alibaba] Unlock '…' … accepted / rejected` 와 `-> after use 9/10 left` — 실제로 열었을 때 허용/거부, 사용 전후 남은 횟수, 다 써서 사라지는지 |
| | `[Alibaba] Extract '…' wants …` — 탈출 조건을 알리바바 아이템으로 대신 인정했는지 |
| | `[Alibaba] … max uses set to …`, `Sending settings…`, `Server answered…` — 횟수 적용, 서버와 주고받은 설정 |
| 서버 콘솔/로그 | `[AlibabaTreasure] [debug] <맵>: N loose-loot spot(s) that can hold keys now include …` — 그 맵 테이블에 몇 곳 들어갔는지 |
| | `[debug] <맵>: no treasure drawn into this raid's loot` — 이번 판엔 안 뽑힘 (뽑히면 디버그와 상관없이 `this raid's loot holds …`) |

- 같은 문을 계속 보고 있을 때처럼 결과가 같으면 한 번만 남습니다.
- 연구소·래버린스 입장 차감은 따로 로그를 남기지 않습니다 — 들어간 뒤 출입증 툴팁의 "남은 입장 횟수"로 확인하세요.

아이템마다(`01. 알리바바의 키카드`, `02. 알리바바의 열쇠`, `03. 알리바바의 마크방 열쇠`, `04. 알리바바의 연구소 출입증`, `05. 알리바바의 래버린스 출입증`) 같은 6개 항목이 있습니다.
출입증의 "사용 가능 횟수"는 곧 **입장 가능 횟수**입니다.

| 항목 | 범위 | 기본 | 언제 적용 |
|---|---|---|---|
| 플리마켓 가격 (₽) | 10,000 ~ 50,000,000 | 5,000,000 / 3,000,000 / 8,000,000 / 2,000,000 / 1,500,000 | 바로 — 기존 매물을 내리고 새 가격으로 다시 올림 |
| 사용 가능 횟수 | 1 ~ 100 | 10 | 바로 — 다음에 문을 열 때부터 |
| 무제한 사용 | 켜기/끄기 | 꺼짐 | 바로 (켜면 횟수 무시) |
| 맵 바닥 등장 확률 (%) | 0 ~ 100, **0.1 단위** | **0 (안 나옴)** | 다음 레이드부터 |
| 컨테이너 등장 확률 (%) | 0 ~ 100, **0.1 단위** | **0 (안 나옴)** | 다음 레이드부터 |
| 봇 소지 확률 (%) | 0 ~ 100, **0.1 단위** | **0 (안 나옴)** | 다음에 생성되는 봇부터 |

- **확률의 뜻** (LotsofLoot 방식 — 맵 루트 테이블에 가중치로 들어감)
  - 맵 바닥: **열쇠·키카드가 나올 수 있는 바닥 자리**(마크방 포함)에서 아이템이 정해질 때마다 그 확률로 이 아이템. 열쇠 안 나오는 자리에는 안 들어갑니다.
  - 컨테이너: **열쇠가 들어 있을 수 있는 컨테이너 종류**(재킷·서랍·더플백·죽은 스캐브)가 한 칸을 채울 때마다 그 확률로 이 아이템.
  - 봇: **봇 한 명마다** 그 확률로 1개를 갖고 나옵니다. 봇은 한 판에 수십 명이라 1%만 해도 자주 보입니다. 플레이어 스캐브는 제외.
- **대략 얼마나 나오나** (SPT 4.1.6 기본 맵 데이터로 계산한 한 판 기대값, 아이템 1종 기준 · LotsofLoot 등 루트 모드를 쓰면 더 많아짐)

  | 맵 | 바닥 0.1% | 바닥 1% | 컨테이너 0.1% | 컨테이너 1% |
  |---|---|---|---|---|
  | 세관 | 0.01개 (100판에 1) | 0.09개 (11판에 1) | 0.11개 (9판에 1) | 1.1개 |
  | 리저브 | 0.01개 | 0.05개 (20판에 1) | 0.37개 (3판에 1) | 3.7개 |
  | 시내 | 0.01개 | 0.15개 (7판에 1) | 0.65개 (2판에 1) | 6.5개 |

  컨테이너가 바닥보다 훨씬 자주 나옵니다(열쇠 나오는 컨테이너 칸이 한 판에 100~650개, 바닥 자리는 5~15번).
- 0.1% 같은 작은 값은 슬라이더 옆 칸에 **숫자를 직접 입력**하세요.
- 설정은 **서버의 `config\config.json`에 저장**됩니다(서버 재시작 후에도 유지). 게임을 켤 때 서버 값을 읽어와 F12에 채웁니다.

## 설치

1. 서버 zip(`AlibabaTreasure-Server-1.5.0.zip`)과 클라 zip(`AlibabaTreasure-Client-1.5.0.zip`)을 `E:\SPT 4.1` 에 그대로 풀기
   (zip 안 폴더 구조가 `SPT_Runtime\user\mods\...`, `BepInEx\plugins\...` 로 되어 있습니다).
2. 서버를 한 번 켜면 `SPT_Runtime\user\mods\AlibabaTreasure\config\config.json` 이 만들어집니다.
3. 서버 로그에 `[AlibabaTreasure] registered 5 item(s)` 와 `Raid entry accepted on: laboratory, labyrinth` 비슷한 줄이 보이면 정상입니다.
4. 예전 버전을 쓰던 경우: `config.json`에 새 아이템 칸(마크방 열쇠·연구소 출입증·래버린스 출입증)이 기본값으로 자동 추가됩니다. 1.0.0에서 저장된 일반 열쇠 가격(6,000,000)은 그대로 남으니 F12에서 바꾸세요.

## 동작 방식 (궁금한 사람만)

- **아이템**: 서버가 시작할 때(`Preload` 단계) 인터체인지 #11SR 카드·키바 암스 열쇠·314 마크 열쇠·랩스 검은 카드·래브리스 카드를 복제해 새 아이템 5개로 등록합니다.
  이름/설명은 한국어 게임이면 한국어, 아니면 영어로 들어갑니다.
- **문 열기**: 게임은 문을 열 때 "갖고 있는 열쇠의 ID == 문이 요구하는 ID" 를 확인합니다.
  클라 플러그인은 알리바바 아이템을 쓸 때만 **그 확인 순간에만** 문이 요구하는 ID를 알리바바 아이템 ID로 잠깐 바꿨다가 바로 되돌립니다.
  그래서 사용 횟수 차감·다 쓰면 사라지는 처리는 **게임 원래 코드가 그대로** 합니다.
  (원본 SkeletonKey는 게임 코드 중간에 비교문을 끼워 넣는 방식이었습니다.)
- **탈출구**: 게임의 "아이템 소지" 탈출 조건 검사(`HasItemRequirement`)에 후처리를 걸어, 요구 아이템이 열쇠/키카드이고 그걸 대신하는 알리바바 아이템이 있으면 통과로 바꿉니다.
- **연구소·래버린스 입장**: 서버가 1회용 연구소 출입 카드를 받는 맵(연구소)에는 연구소 출입증을, 래브리스 카드를 받는 맵(래버린스)에는 래버린스 출입증을 "입장 키 목록"에 추가합니다. 게임은 이 목록 하나로 메뉴 입장 검사와 레이드 시작 시 횟수 차감을 둘 다 하므로, 차감도 게임 원래 코드가 합니다.
- **맵 등장**: LotsofLoot가 마크방에 추가 아이템을 넣는 방식과 같습니다. 서버가 맵 루트 테이블을 읽을 때마다(변환기) 열쇠·키카드가 원래 들어 있는
  바닥 자리 후보 목록과 컨테이너 종류 목록에 알리바바 아이템을 가중치 `원래 합계 × p / (100 − p)`로 추가합니다 → 그 자리 추첨에서 정확히 p% 몫.
  자리 배치·칸 맞추기는 게임 원래 생성기가 하므로 겹칠 일이 없고, LotsofLoot와 같이 써도 충돌하지 않습니다(LotsofLoot의 배수가 그대로 곱해짐).
  F12에서 확률을 바꾸면 캐시된 테이블을 비워 다음 레이드부터 새 값으로 다시 만듭니다. 서버 로그에 `this raid's loot holds …`로 실제로 나온 판을 알려 줍니다.
- **봇**: 봇 소지품을 만드는 중(칸 계산이 살아있을 때)에 주머니 → 조끼 → 가방 순으로 빈 칸에 넣습니다. 자리가 없으면 그냥 안 넣습니다.

- 2026-10-10 1.3.0: 5종 설정 통신·래버린스 입장 목록 추가는 시험 실행으로 확인, 실제 입장·툴팁 표시는 미검증.

- 2026-10-10 1.1.0: 설정 3종 통신·1.0.0 설정 호환·입장 키 목록 추가는 시험 실행으로 확인, 탈출구·랩스 입장·마크방 구분은 코드상 그래야 함(미검증).
- 열쇠가 필요한 탈출구는 대부분 "잠긴 문 너머에 있는 탈출구"라서 **문 열기 쪽으로 처리**됩니다. 탈출 조건 자체가 "열쇠 소지"인 경우는 SPT 서버 데이터에는 없고
  맵 파일 쪽에 정의돼 있어 어떤 맵에 몇 개 있는지는 확인하지 못했습니다 — 있으면 위 후처리로 통과됩니다(미검증). "아이템을 넘겨주는" 형식(차량 탈출의 돈 등)은 대상이 아닙니다.
- 출입증의 남은 횟수를 F12에서 현재 사용량보다 낮게 줄이면, 게임의 입장 차감 코드가 "정확히 같을 때만" 지우는 방식이라 그 카드는 입장으로는 안 사라집니다(문 열 때는 정상적으로 사라짐).
- 다른 모드가 같은 아이템 ID를 쓰면 서버 로그에 경고를 남기고 등록을 건너뜁니다.

## 직접 빌드

```
dotnet build server -c Release      # 서버 모드 + release\AlibabaTreasure-Server-1.5.0.zip
dotnet build client -c Release      # 클라 플러그인 + release\AlibabaTreasure-Client-1.5.0.zip
```

- 게임 경로는 기본 `E:\SPT 4.1` (`Directory.Build.props`). 다르면 `-p:SptRoot=경로` 또는 `local.props`.
- 윈도우에서 빌드하면 결과물이 위 설치 위치로 바로 복사됩니다(게임/서버가 켜져 있으면 `-p:SkipDeploy=true`).
- 서버 `net10.0`, 클라 `netstandard2.1`. 클라는 게임 폴더의 `Assembly-CSharp`, `Comfort`, `ItemComponent.Types`, `Sirenix.Serialization`, BepInEx/Harmony를 참조합니다.
